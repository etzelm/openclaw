# Production path of the memory schema admission (measured AFTER build b12191867f0, whose production source equals the final commit, see tree-identity.out; same files in BEFORE d4d2c3dd1e3)

Paths are relative to the tree root.

## What production does at memory store open
- Manager creation calls `MemoryIndexDatabase.openPublished` with `schema: { cacheEnabled: effectiveSettings.cache.enabled, ftsEnabled: effectiveSettings.query.hybrid.enabled, ftsTokenizer: effectiveSettings.store.fts.tokenizer }` (extensions/memory-core/src/memory/manager.ts:151-161). Their defaults are true (`query.hybrid.enabled`), `"unicode61"` (`store.fts.tokenizer`) and true (`cache.enabled`, `DEFAULT_CACHE_ENABLED`), src/agents/memory-search.ts:121-122, 200-201, 65 and 211 (admission-param-defaults.out); the harness uses cacheEnabled=true, ftsEnabled=true, ftsTokenizer="unicode61" (the same triple extensions/memory-core/src/migration/doctor-memory-sidecar.ts:440 uses, and the tokenizer of the stores' admitted FTS DDL, see store-facts.out). `ftsTable` is not passed, so the canonical `memory_index_chunks_fts` is used (packages/memory-host-sdk/src/host/memory-schema.ts:361-368).
- `openPublished` -> `initializePublishedMemory` (extensions/memory-core/src/memory/manager-database-context.ts:84-87; manager-publication.ts:35-60) opens the agent worker store with `openOpenClawAgentSqliteWorkerStoreV2(..., { input: { kind: "agent" } })` (manager-publication.ts:40-49), calls `worker.prepare()`, then `worker.execute({ type: "schema.admit", input: schema })` under `retryMemoryPublication` busyTimeoutMs 5000 (manager-publication.ts:50-55). `admitSchema` in manager-database-context.ts:561-566 does the same via `executePublication`.

## (a) Opener, pragmas, handler
- Production agent path (`kind: "agent"`): the worker does not open its own connection. `bindSqliteWorkerBackend` borrows the agent database owner's executor connection and only reads its `busy_timeout` and `foreign_keys` pragmas (extensions/memory-core/src/memory/manager-publication.worker.ts:166-195). The agent opener itself lives in src/state (`openOpenClawAgentSqliteWorkerStoreV2`, src/state/openclaw-agent-worker-store.ts:195-206).
- Private shadow path (`createSqliteWorkerBackend` / `openShadowBackend`): `openNodeSqliteDatabase(path, { allowExtension })` then `configureMemorySqliteWalMaintenance(db, { busyTimeoutMs: 5_000, databasePath })` (manager-publication.worker.ts:112-114, 126-148).
- `schema.admit` handler (manager-publication.worker.ts:414-418): `PRAGMA foreign_keys = OFF`; `write(() => ensureMemoryIndexSchema({ ...command.input, db }))`; if ok `admitSqliteSchema(db)`; then `withFacts` (readMemoryDatabaseFacts) and restore `foreign_keys` in `finally`. `write` = `setSqliteBusyTimeout(db, 0)` then `runSqliteImmediateTransactionSync` (BEGIN IMMEDIATE ... COMMIT) with admission hooks (`admit("transaction")`/`admit("commit")`) and a write scope (manager-publication.worker.ts:257-310; withFacts :341).

## (b) First call in a FRESH process
- Admission receipts are in-process memory (`getSqliteDatabaseAdmission` reads `state.local` / `record.facts`, src/infra/sqlite-database-admission-read.ts:64-124). Nothing is persisted in the database file, so a fresh process finds no receipt and takes the FIRST-ADMISSION path in `ensureMemoryIndexSchema`: it falls through the `if (admitted)` branch (packages/memory-host-sdk/src/host/memory-schema.ts:386-402), re-runs the strict-schema migration check (`migrateStrict`, :482) and `admitStoreSearch` (:510) -> `admitSqliteMemoryTextSearch`, which opens `SAVEPOINT ensure_memory_search` (src/infra/database-engine/sqlite-search-schema.ts:223) and calls `reconcileMemoryChunkFtsRows` (:230). Finally `publishSqliteDatabaseAdmission` (:522).
- Observed: every fresh-process measurement logs path=first-admission (settle.out, measure-admission-*.out). Caveat, unverified: in the real gateway the host process may already hold a receipt that the worker obtains through the admission exchange (sqlite-database-admission-read.ts:112-123 `exchange`), in which case call 1 in a restarted gateway could take the admitted path. The harness cannot reproduce that exchange.

## (c) Second call in the same process
- A valid receipt exists, so `ensureMemoryIndexSchema` takes the ADMITTED path (memory-schema.ts:386-402): `backfillMemoryChunkProvenance`, then (inside the already open BEGIN IMMEDIATE, `db.isTransaction`) `reconcileMemoryChunkFtsRows` (:393-399, :401 `return admitted`).
- Observed with CALLS=2 on the dev copy: call 1 first-admission, call 2 admitted, both run exactly one derived_count statement (evidence/two-calls-check.out, both arms).

## The changed statement
`reconcileMemoryChunkFtsRows` (src/infra/database-engine/sqlite-search-schema.ts:166-184); `derived_count` is at :177 (AFTER: `FROM ${ftsTable}_docsize`; BEFORE: `FROM ${ftsTable}`). It runs on BOTH paths, once per admission.

## What the harness (measure-admission.mjs) differs from production in
1. It cannot use the production worker handler: `createSqliteWorkerBackend().execute` needs the host admission broker (`requestSqliteWorkerOperationAdmission` throws "SQLite operation requires its retained admission" outside a broker scope, src/infra/sqlite-writer-admission-client.ts:37-44). It also cannot use the agent opener: the snapshots are agent DB schema version 24 and `openOpenClawAgentSqliteWorkerStoreV2` refuses them ("run openclaw doctor --fix"); migrating them would change the stores.
2. It therefore calls the same built exports (`openNodeSqliteDatabase`, `configureMemorySqliteWalMaintenance` busy 5000, `setSqliteBusyTimeout`, `runSqliteImmediateTransactionSync`, `ensureMemoryIndexSchema`, `admitSqliteSchema` from dist/plugin-sdk) in the handler's order, on the main thread, with the shadow-style connection. Missing versus production: the worker thread hop, `admit()` broker hooks, `withSqliteDatabaseWriteScope`, `readMemoryDatabaseFacts` after the call, and the agent executor's own pragmas. These are identical for BEFORE and AFTER, so they do not bias the difference, but they make absolute numbers a lower bound of the worker-path cost.
3. The harness wraps `DatabaseSync.prototype.prepare/exec` to observe the path and time the `derived_count` statement; the wrapper cost is tiny and equal across arms.
