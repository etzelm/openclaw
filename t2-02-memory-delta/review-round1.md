## Questions a maintainer would ask

Q1. The planner, header, retained rows and kernel branch were built for session transcripts and #40919's accepted shape was "session-only". Has anyone asked for this on memory files, and is a second source on the delta path wanted, given the extra surface on a path that #170302 just simplified? (This is the question the product cap hangs on; the body cannot answer it, only state facts.)

Q2. The memory-only fallback adds a branch to a shared planner on the strength of a cost claim ("scalar vector deletes per removed id where `clear()` issues one path-scoped scan") that the harness could not measure because it has no sqlite-vec. Why keep an unmeasured special case instead of the planner's existing `keep.size === 0` exit alone? What happens at 33 removed ids with 1 retained row (all-or-nothing means this takes scalar deletes)?

Q3. For a clean semantic index the old reuse path probed the vector table per chunk (`findVector`) and wrote any missing vector row, which self-healed gaps. The delta never writes retained rows' vectors.
